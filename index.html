⑤ 최종 테스트

요구사항대로 동작하는지 하나씩 눌러 보기

이 자료의 연습 과제(회원·일정) 기준 예시입니다. 실제 시험에서는 그 문제지의 요구사항 목록으로 확인하세요.

  • 메뉴 — 일정등록·회원현황·일정현황·홈으로가 모두 가운데 iframe 안에서 열리는지 (새 창으로 열리면 target/name 오타)
  • 조회 화면 — 회원 5건, 일정 4건이 나오는지, 날짜가 지정한 형식(yyyy-MM-dd)인지
  • 입력 검증 — 일정일자·회원코드·일정메모를 하나씩 비우고 등록을 눌러 알림창과 커서 이동이 맞는지
  • 등록 — 정상 입력 후 안내창 → 홈으로 이동, 일정현황에 새 행이 보이는지, 일정코드가 자동으로 다음 번호가 되는지
  • 한글 — 한글 메모를 등록해도 깨지지 않는지 (깨지면 단계 2의 UTF-8 설정과, POST로 보낼 경우 setCharacterEncoding 위치를 확인)
  • 화면 모양 — header·nav·footer 색과 정렬이 요구사항과 같은지
⑥ 검토를 받기 위한 데이터 초기화

테스트 흔적을 지우고 처음 상태로

  • 테스트하면서 등록한 일정이 테이블에 남아 있으므로, 검토를 받기 전에 db.sql을 다시 Execute All(단계 9) 합니다.
  • db.sql은 맨 위에서 테이블을 지우고(DROP) 다시 만들고 넣기 때문에, 실행하면 회원 5건 · 일정 4건의 처음 상태로 돌아갑니다. 일정등록 화면의 자동 번호도 다시 5부터 시작합니다.
  • 초기화한 뒤 회원현황·일정현황을 한 번 열어 처음 데이터가 보이는지만 확인하면 됩니다.

완성된 앱은 이렇게 동작합니다

Chapter 3까지 끝낸 뒤의 요청 흐름입니다.

  1. A 접속 — index.jsp를 열면 header·nav·footer와, 기본 화면 main.jsp가 담긴 iframe이 함께 뜹니다.
  2. 메뉴 클릭 (그림의 회색 화살표) — 메뉴의 target="section_page" 때문에 iframe 안의 내용만 바뀝니다. 바깥 틀은 그대로입니다.
  3. B 제출 — reg.jsp의 필수입력 검증을 통과하면 폼이 action.jsp로 넘어가 INSERT가 실행됩니다.
  4. C 완료 (그림의 점선) — action.jsp가 안내창을 띄운 뒤 main.jsp로 되돌려 보냅니다.

Workspace
Eclipse가 프로젝트와 설정을 저장하는 작업 폴더 (이 실습: C:\sample)
JDK
Java 프로그램을 컴파일하고 실행하는 도구 모음
Eclipse (IDE)
코드 작성·실행·서버 관리를 한 화면에서 하는 개발 도구
Tomcat (WAS, 웹 애플리케이션 서버)
브라우저 요청을 받아 JSP를 실행하고, 결과 HTML을 돌려주는 웹 애플리케이션 서버
JSP
HTML 안에 Java 코드를 섞어 쓴 파일. 서버(Tomcat)에서 실행된다
스크립틀릿 <% %>
JSP 안에서 서버가 실행하는 Java 코드 영역
JDBC · 드라이버
JDBC는 Java가 DB와 대화하는 표준 방법, 드라이버(ojdbc8.jar)는 그 방법을 Oracle용으로 만든 파일
SQL
DB에 테이블을 만들고, 데이터를 넣고, 꺼내는 언어
테이블 · 컬럼 · 행
엑셀에 비유하면 시트 · 열 · 한 줄
PK (기본키)
행 하나를 구분하는 값. 중복·빈 값 불가 (예: 회원코드 M0001)
FK (외래키)
다른 테이블의 키(보통 PK)를 참조하는 컬럼. 값을 넣으면 참조하는 테이블에 실제로 있는 값이어야 한다. 외래키만으로 NULL이 막히지는 않으므로 필요하면 NOT NULL을 따로 선언한다 (예: 일정의 회원코드)
COMMIT
지금까지 바꾼 데이터를 확정해 저장하는 명령
iframe
페이지 안에 다른 페이지를 끼워 보여주는 창. 메뉴를 누르면 이 안의 내용만 바뀐다
WEB-INF/lib
웹 프로젝트가 실행될 때 쓸 jar 파일을 두는 폴더
Build Path
Eclipse가 Java 코드를 컴파일할 때 참고하는 라이브러리 목록
서블릿
요청을 처리하는 Java 클래스. JSP도 실행 전에 서블릿으로 바뀐다
트랜잭션
함께 성공하거나 함께 취소되어야 하는 작업 묶음
Auto Commit
SQL을 실행할 때마다 자동으로 COMMIT하는 설정
SID · Service Name
Oracle에서 접속할 대상을 가리키는 이름 두 종류. 11g XE는 SID가 xe. 21c XE는 서비스 XE(루트 컨테이너)와 XEPDB1(기본 PDB)이 따로 있다
시맨틱 태그
header·nav·section·footer처럼 영역의 의미를 나타내는 HTML 태그
PreparedStatement
값을 ? 자리에 따로 넣어 SQL을 실행하는 방식. 문자열을 직접 이어 붙이는 것보다 안전하다
SQL 인젝션
입력값에 SQL을 섞어 넣어 의도하지 않은 SQL이 실행되게 하는 공격
GET · POST
폼 전송 방식. GET은 값이 주소(URL)에 붙어 가고, POST는 요청 본문에 담겨 간다. method를 안 쓰면 GET
jar 파일
Java 부품(클래스)을 하나로 묶은 파일. ojdbc8.jar가 대표 예
localhost
지금 쓰고 있는 내 컴퓨터를 가리키는 주소
포트
한 컴퓨터 안에서 프로그램을 구분하는 번호. 이 실습은 Tomcat 8090, Oracle 1521
Context path
주소에서 프로젝트를 가리키는 부분. localhost:8090/default/index.jsp의 default
404
요청한 파일을 서버가 찾지 못했다는 오류 번호. 파일 이름·위치·주소 오타를 확인
Connection · Statement · ResultSet
차례로 DB와의 연결, SQL을 실어 보내는 도구, 조회 결과 표. 다 쓰면 close()로 닫는다
try-with-resources
try ( ) 괄호 안에서 연 자원을 블록이 끝날 때 자동으로 닫아 주는 Java 문법
readonly
입력칸을 읽기 전용으로 만드는 속성. 화면에서는 못 고치지만 값은 함께 전송된다
alert · focus
alert는 안내창을 띄우는 JavaScript 명령, focus는 커서를 특정 입력칸으로 옮기는 명령
기준 코드
이 자료가 권하는 따라 쓸 코드. 수업 당시 캡처와 다른 곳은 각 해설에 적어 두었다

  • 재응시: 외부평가에서 불합격하면 최초로 응시한 외부평가의 합격자 공고일 이후 2년 이내에 실시되는 외부평가에 다시 응시할 수 있습니다. 개인별 응시 가능 기간은 CQ-Net에서 확인하세요.
🔎
비율 계산외부평가 비중 50%를 PDF의 1차 40% : 2차 60%로 나누면 50 × 0.4 = 20%, 50 × 0.6 = 30%이므로 필기 20% · 실무 30%가 됩니다.

form 태그 사용법

form은 입력칸들을 한 묶음으로 만들어 서버의 JSP로 보내는 태그입니다. 시험 과제의 등록 화면은 모두 form으로 만듭니다. 입력칸 종류마다 생김새와 JSP에서 값을 꺼내는 방법이 조금씩 다르니, 아래 실험실에서 직접 바꿔 보며 익히세요.

B-1. form 태그에 쓰는 속성

<form action="action.jsp" method="post" name="fm" onsubmit="return check_val()">
    ... 입력칸들 ...
</form>
속성하는 일이 자료의 예
action값을 받을 파일action="action.jsp"
method보내는 방식. get은 값이 주소창 뒤에 붙고(안 쓰면 get), post는 주소창에 보이지 않게 요청 본문에 담아 보냅니다method="post"
name자바스크립트에서 이 폼을 부르는 이름name="fm" → document.fm
onsubmit보내기 직전에 실행할 검사. false가 돌아오면 보내지 않습니다onsubmit="return check_val()"
target결과를 열 창 이름. iframe 이름을 적으면 그 안에서 열립니다이 과제의 메뉴 링크(a 태그)에서 씀
enctype파일을 올릴 때만 multipart/form-data로 바꿉니다이 과제에서는 쓰지 않음

B-2. 직접 해 보기: 무엇이 서버로 가나

B-3. 입력칸 유형별 정리

카드 오른쪽 미리보기를 바꾸면 그 아래에 서버로 가는 값이 나옵니다.

글자 칸 type="text"

가장 많이 쓰는 칸입니다. 일정일자, 회원코드처럼 짧은 글자를 받습니다. value는 처음에 들어 있는 글자, maxlength는 입력할 수 있는 최대 글자 수, size는 칸의 보이는 너비입니다. 1차 필기 단답형에 나온 속성들입니다.

<input type="text" name="fk_member" value="M0001" maxlength="5" size="10">
JSP: request.getParameter("fk_member") → "M0001". 비어 있으면 ""(빈 글자)
미리보기

비밀번호 type="password"

화면에는 ●으로 가려지지만 서버에는 입력한 글자 그대로 갑니다. 가려 주는 것은 화면뿐입니다.

<input type="password" name="admin_pw">
JSP: request.getParameter("admin_pw")
미리보기

숫자 칸 type="number"

숫자만 입력되고 위아래 화살표가 생깁니다. min, max로 범위를 정합니다. 서버에는 숫자가 아니라 글자로 가므로, 계산하려면 바꿔야 합니다.

<input type="number" name="drv_start" min="0">
JSP: Integer.parseInt(request.getParameter("drv_start"))
미리보기

달력 type="date"

달력에서 날짜를 고릅니다. 서버에는 2026-05-01처럼 줄표가 들어간 형식으로 갑니다. 이 자료는 20260501처럼 8자리 글자 칸을 쓰므로, date 칸을 쓴다면 to_date의 형식을 'YYYY-MM-DD'로 바꿔야 합니다.

<input type="date" name="do_day">
JSP: request.getParameter("do_day") → "2026-05-01"
미리보기

숨은 칸 type="hidden"

화면에는 안 보이지만 함께 보내는 값입니다. 사용자가 고를 필요가 없는 값(예: 처리 종류)을 실어 보낼 때 씁니다.

<input type="hidden" name="mode" value="insert">
JSP: request.getParameter("mode") → "insert"
미리보기(화면에 보이는 것이 없습니다)

하나만 고르기 type="radio"

name이 같은 것끼리 한 묶음이 되어 하나만 고를 수 있습니다. 서버에는 고른 것의 value가 갑니다. 아무것도 고르지 않으면 그 name은 가지 않아 null이 됩니다. checked를 적으면 처음부터 골라져 있습니다.

<input type="radio" name="priority" value="H">높음
<input type="radio" name="priority" value="M" checked>보통
JSP: request.getParameter("priority") → "M"
미리보기

여러 개 고르기 type="checkbox"

같은 name으로 여러 개를 두면 체크한 것만 모두 갑니다. 그래서 하나가 아니라 배열로 받습니다. 하나도 체크하지 않으면 아무것도 가지 않습니다.

<input type="checkbox" name="notify" value="sms">문자
<input type="checkbox" name="notify" value="mail">메일
JSP: request.getParameterValues("notify") → {"sms", "mail"}
미리보기

고르는 상자(콤보박스) <select>

공식 과제의 부서코드처럼 정해진 값 중 하나를 고를 때 씁니다. 화면에는 option 사이의 글자가 보이고, 서버에는 value가 갑니다. 첫 줄을 value=""로 두면 '아직 안 골랐음'을 검사할 수 있습니다. selected를 적으면 처음부터 골라져 있습니다.

<select name="dept_code">
  <option value="">부서</option>
  <option value="10">[10]영업부</option>
  <option value="20">[20]총무부</option>
</select>
JSP: request.getParameter("dept_code") → "10"
미리보기

여러 줄 글자 <textarea>

긴 메모처럼 여러 줄을 받습니다. value 속성 대신 여는 태그와 닫는 태그 사이에 처음 글자를 적습니다. rows는 줄 수, cols는 너비입니다.

<textarea name="do_memo" rows="3" cols="30"></textarea>
JSP: request.getParameter("do_memo")
미리보기

읽기 전용과 꺼 둔 칸 readonly · disabled

둘 다 화면에서 고칠 수 없지만, readonly는 서버로 가고 disabled는 가지 않습니다. 그래서 일정등록의 자동 번호는 readonly로 둡니다.

<input type="text" name="pk_schedule" value="5" readonly>
<input type="text" name="writer" value="관리자" disabled>
JSP: pk_schedule은 받을 수 있고, writer는 null
미리보기

버튼 세 가지 submit · reset · button

submit은 폼을 보냅니다(onsubmit 검사를 먼저 거침). reset은 입력칸을 처음 값으로 되돌립니다. button은 아무 일도 하지 않으므로 onclick으로 할 일을 정해 줍니다(예: 조회 화면으로 이동, 다시쓰기 안내).

<input type="submit" value="등록">
<input type="reset" value="취소">
<input type="button" value="조회" onclick="location.href='list_j.jsp'">
버튼의 value는 name이 없으면 서버로 가지 않습니다
미리보기

이름표 <label>

입력칸 옆 글자를 label로 감싸면 글자를 눌러도 입력칸이 선택됩니다. 작은 체크박스나 라디오를 누르기 쉬워집니다.

<label><input type="checkbox" name="agree" value="Y"> 동의합니다</label>
서버로 가는 값은 input의 것입니다. label 글자는 가지 않습니다

1차 필기 연결형 문제에 이 세 메서드와 설명을 짝짓는 문제가 나왔습니다.

메서드돌려주는 것쓰는 때
getParameter("이름")값 하나(String). 그 이름이 없으면 nulltext, select, radio, textarea, hidden

String[] notify = request.getParameterValues("notify");
if (notify != null) {
    for (String n : notify) {

B-6. 작은따옴표도 안전하게: PreparedStatement

단계 18의 action.jsp는 값을 SQL 문자열에 이어 붙입니다. 메모에 작은따옴표(')가 들어가면 SQL이 중간에 끊겨 오류가 납니다. 시험 데이터에는 작은따옴표가 없어서 단계 18 방식으로 충분하지만, 이 문제를 피하는 방법은 알아 두세요.

// 단계 18 방식 : 값을 이어 붙인다
Statement stmt = conn.createStatement();
String sql = "insert into tbl_schedule values("
           + pk_schedule + ", "
           + "to_date('" + do_date + "', 'YYYYMMDD'), "
           + "'" + do_memo + "', "
           + "'" + fk_member + "')";
stmt.executeUpdate(sql);
// PreparedStatement : ? 자리에 값을 따로 넣는다
String sql = "insert into tbl_schedule values("
           + "?, to_date(?, 'YYYYMMDD'), ?, ?)";
PreparedStatement pstmt = conn.prepareStatement(sql);
pstmt.setInt(1, Integer.parseInt(pk_schedule));
pstmt.setString(2, do_date);
pstmt.setString(3, do_memo);
pstmt.setString(4, fk_member);
pstmt.executeUpdate();

setInt·setString의 첫 숫자는 몇 번째 ?인지를 뜻합니다. 값과 SQL 문법이 따로 가기 때문에 따옴표를 직접 붙이지 않고, 작은따옴표가 든 메모도 그대로 저장됩니다.
