⑤ 최종 테스트

요구사항대로 동작하는지 하나씩 눌러 보기

이 자료의 연습 과제(회원·일정) 기준 예시입니다. 실제 시험에서는 그 문제지의 요구사항 목록으로 확인하세요.

  • 메뉴 — 일정등록·회원현황·일정현황·홈으로가 모두 가운데 iframe 안에서 열리는지 (새 창으로 열리면 target/name 오타)
  • 조회 화면 — 회원 5건, 일정 4건이 나오는지, 날짜가 지정한 형식(yyyy-MM-dd)인지
  • 입력 검증 — 일정일자·회원코드·일정메모를 하나씩 비우고 등록을 눌러 알림창과 커서 이동이 맞는지
  • 등록 — 정상 입력 후 안내창 → 홈으로 이동, 일정현황에 새 행이 보이는지, 일정코드가 자동으로 다음 번호가 되는지
  • 한글 — 한글 메모를 등록해도 깨지지 않는지 (깨지면 단계 2의 UTF-8 설정과, POST로 보낼 경우 setCharacterEncoding 위치를 확인)
  • 화면 모양 — header·nav·footer 색과 정렬이 요구사항과 같은지
⑥ 검토를 받기 위한 데이터 초기화

테스트 흔적을 지우고 처음 상태로

  • 테스트하면서 등록한 일정이 테이블에 남아 있으므로, 검토를 받기 전에 db.sql을 다시 Execute All(단계 9) 합니다.
  • db.sql은 맨 위에서 테이블을 지우고(DROP) 다시 만들고 넣기 때문에, 실행하면 회원 5건 · 일정 4건의 처음 상태로 돌아갑니다. 일정등록 화면의 자동 번호도 다시 5부터 시작합니다.
  • 초기화한 뒤 회원현황·일정현황을 한 번 열어 처음 데이터가 보이는지만 확인하면 됩니다.

완성된 앱은 이렇게 동작합니다

Chapter 3까지 끝낸 뒤의 요청 흐름입니다.

  1. A 접속 — index.jsp를 열면 header·nav·footer와, 기본 화면 main.jsp가 담긴 iframe이 함께 뜹니다.
  2. 메뉴 클릭 (그림의 회색 화살표) — 메뉴의 target="section_page" 때문에 iframe 안의 내용만 바뀝니다. 바깥 틀은 그대로입니다.
  3. B 제출 — reg.jsp의 필수입력 검증을 통과하면 폼이 action.jsp로 넘어가 INSERT가 실행됩니다.
  4. C 완료 (그림의 점선) — action.jsp가 안내창을 띄운 뒤 main.jsp로 되돌려 보냅니다.

자료 곳곳에 나오는 용어를 한 줄로 풀었습니다. 막히면 여기로 돌아와 확인하세요.

Workspace
Eclipse가 프로젝트와 설정을 저장하는 작업 폴더 (이 실습: C:\sample)
JDK
Java 프로그램을 컴파일하고 실행하는 도구 모음
Eclipse (IDE)
코드 작성·실행·서버 관리를 한 화면에서 하는 개발 도구
Tomcat (WAS, 웹 애플리케이션 서버)
브라우저 요청을 받아 JSP를 실행하고, 결과 HTML을 돌려주는 웹 애플리케이션 서버
JSP
HTML 안에 Java 코드를 섞어 쓴 파일. 서버(Tomcat)에서 실행된다
스크립틀릿 <% %>
JSP 안에서 서버가 실행하는 Java 코드 영역
JDBC · 드라이버
JDBC는 Java가 DB와 대화하는 표준 방법, 드라이버(ojdbc8.jar)는 그 방법을 Oracle용으로 만든 파일
SQL
DB에 테이블을 만들고, 데이터를 넣고, 꺼내는 언어
테이블 · 컬럼 · 행
엑셀에 비유하면 시트 · 열 · 한 줄
PK (기본키)
행 하나를 구분하는 값. 중복·빈 값 불가 (예: 회원코드 M0001)
FK (외래키)
다른 테이블의 키(보통 PK)를 참조하는 컬럼. 값을 넣으면 참조하는 테이블에 실제로 있는 값이어야 한다. 외래키만으로 NULL이 막히지는 않으므로 필요하면 NOT NULL을 따로 선언한다 (예: 일정의 회원코드)
COMMIT
지금까지 바꾼 데이터를 확정해 저장하는 명령
iframe
페이지 안에 다른 페이지를 끼워 보여주는 창. 메뉴를 누르면 이 안의 내용만 바뀐다
WEB-INF/lib
웹 프로젝트가 실행될 때 쓸 jar 파일을 두는 폴더
Build Path
Eclipse가 Java 코드를 컴파일할 때 참고하는 라이브러리 목록
서블릿
요청을 처리하는 Java 클래스. JSP도 실행 전에 서블릿으로 바뀐다
트랜잭션
함께 성공하거나 함께 취소되어야 하는 작업 묶음
Auto Commit
SQL을 실행할 때마다 자동으로 COMMIT하는 설정
SID · Service Name
Oracle에서 접속할 대상을 가리키는 이름 두 종류. 11g XE는 SID가 xe. 21c XE는 서비스 XE(루트 컨테이너)와 XEPDB1(기본 PDB)이 따로 있다
시맨틱 태그
header·nav·section·footer처럼 영역의 의미를 나타내는 HTML 태그
PreparedStatement
값을 ? 자리에 따로 넣어 SQL을 실행하는 방식. 문자열을 직접 이어 붙이는 것보다 안전하다
SQL 인젝션
입력값에 SQL을 섞어 넣어 의도하지 않은 SQL이 실행되게 하는 공격
GET · POST
폼 전송 방식. GET은 값이 주소(URL)에 붙어 가고, POST는 요청 본문에 담겨 간다. method를 안 쓰면 GET
jar 파일
Java 부품(클래스)을 하나로 묶은 파일. ojdbc8.jar가 대표 예
localhost
지금 쓰고 있는 내 컴퓨터를 가리키는 주소
포트
한 컴퓨터 안에서 프로그램을 구분하는 번호. 이 실습은 Tomcat 8090, Oracle 1521
Context path
주소에서 프로젝트를 가리키는 부분. localhost:8090/default/index.jsp의 default
404
요청한 파일을 서버가 찾지 못했다는 오류 번호. 파일 이름·위치·주소 오타를 확인
Connection · Statement · ResultSet
차례로 DB와의 연결, SQL을 실어 보내는 도구, 조회 결과 표. 다 쓰면 close()로 닫는다
try-with-resources
try ( ) 괄호 안에서 연 자원을 블록이 끝날 때 자동으로 닫아 주는 Java 문법
readonly
입력칸을 읽기 전용으로 만드는 속성. 화면에서는 못 고치지만 값은 함께 전송된다
alert · focus
alert는 안내창을 띄우는 JavaScript 명령, focus는 커서를 특정 입력칸으로 옮기는 명령
기준 코드
이 자료가 권하는 따라 쓸 코드. 수업 당시 캡처와 다른 곳은 각 해설에 적어 두었다

최종 점수와 합격 기준

합격 기준과 재응시 기간은 CQ-Net 과정평가형 자격 FAQ(2026-10-16 확인)를 따랐습니다. FAQ는 내부평가와 외부평가를 1:1로 합산해 평균 80점 이상이면 합격이라고 안내합니다. 외부평가 안의 배점(1차 40%, 2차 60%)은 25V5 공식 PDF의 내용입니다.

최종 점수 100점 중합격: 평균 80점 이상 · 재응시: 합격자 공고일 이후 2년 이내
내부평가 50%
필기 20%
실무 30%
  • 내부평가(교육기관에서 하는 평가) 100점 만점 → 50% 반영
  • 외부평가 필기(1차) 100점 만점 → 20% 반영
  • 외부평가 실무(2차 작업형) 100점 만점 → 30% 반영
  • 최종 점수 = 내부 × 0.5 + 필기 × 0.2 + 실무 × 0.3, 80점 이상이면 합격
  • 재응시: 외부평가에서 불합격하면 최초로 응시한 외부평가의 합격자 공고일 이후 2년 이내에 실시되는 외부평가에 다시 응시할 수 있습니다. 개인별 응시 가능 기간은 CQ-Net에서 확인하세요.

2. 2차 공식 예시 과제: 차량주행관리 프로그램

문제지의 "수행 작업"은 크게 네 덩어리이고, 아래 순서로 적혀 있습니다. 조회·등록 화면은 테이블과 데이터가 있어야 확인할 수 있으므로, 2)·3)을 먼저 끝내고 4)를 하는 것도 방법입니다(이 자료의 의견).

  1. 메인화면 완성 — 제공되는 스타일시트(main.css)와 요구사항을 참고해 header / nav / section / footer 구성.

4. 화면별 요구사항

메뉴 5개에 해당하는 화면입니다. 요구사항 문장을 줄여 정리했고, 괄호 안 예시는 원문의 출력 예입니다.

가

시작화면 — index.jsp

  • header, 메뉴(nav), section, footer로 구성. 메뉴는 차량조회 · 주행내역등록 · 주행내역조회 · 부서별주행통계 · 홈으로.
  • footer는 저작권 정보. header·footer 배경 red, 메뉴 글자 black, footer 글자 오른쪽 정렬.
나

차량조회

  • 메뉴를 선택하면 차량 테이블에 입력된 정보를 모두 조회.
  • 항목: 차량번호, 모델, 제조사, 구매일.
  • 구매일은 yyyy년MM월dd일 형식으로 출력 (예: 2023년01월01일).
다

주행내역등록

  • 제목 "주행내역등록"과 폼. 항목: 주행일자, 차량번호, 출발Km, 도착km, 부서코드, 주유금액. 버튼은 주행내역등록과 다시쓰기.
  • 부서코드는 콤보박스. 항목은 HTML에서 직접 스크립트로 작성한다고 되어 있고, 예시 그림의 선택지는 [10]영업부 · [20]총무부 · [30]구매부 · [40]개발부 (처음에는 "부서").
  • 유효성 체크: 비어 있으면 항목별 알림창 — 주행일자 · 차량번호 · 출발Km · 도착km · 주유금액은 "○○가(이) 입력되지 않았습니다!"(예: "주행일자가 입력되지 않았습니다!", "주유금액이 입력되지 않았습니다!"), 부서코드는 "부서코드가 선택되지 않았습니다!". 원문은 주행일자 알림에서 확인을 누르면 포커스가 주행일자로 이동한다고 적고 있습니다.
  • 모두 입력 후 등록하면 DB의 주행내역 테이블에 저장 → "주행내역이 정상적으로 등록 되었습니다!" → 확인 시 메인(시작)화면으로 이동.
  • 다시쓰기: "정보를 지우고 처음부터 다시 입력 합니다!" → 확인 시 입력 화면이 모두 클리어되고 포커스가 주행일자로.
  • 등록할 값은 주행내역 샘플 데이터를 참고하고, 등록 확인은 주행내역조회 화면에서 한다.
라

주행내역조회

  • 주행내역·부서·차량 3개 테이블을 참조해서 주행일자, 차량번호, 모델, 출발km, 도착km, 부서명, 주유금액을 출력.
  • 주행일자: yyyy년MM월dd일 / 출발·도착km: 999,999 형식 (예: 10,000) / 주유금액: 통화기호와 천 단위 구분기호 (예: ₩25,000).
마

부서별주행통계

  • 주행내역·부서 테이블을 참조해 부서코드, 부서명, 총운행거리, 총주유금액을 출력.
  • 총운행거리 = (도착km − 출발km)의 합. 총주유금액은 통화기호 + 천 단위 구분 (예: ₩95,000).
회원·일정 예제에는 이 화면(부서별 합계)에 해당하는 예제가 없습니다. 6절의 후속 연습을 참고하세요.
바

홈으로

  • 메뉴를 클릭하면 메인(시작)화면으로 이동.
🧮
화면 예시와 계산이 맞는지 확인했습니다원문 샘플 10건으로 부서별 합계를 직접 계산하면 영업부 600km / 95,000원, 총무부 650 / 105,000, 구매부 550 / 90,000, 개발부 300 / 40,000으로, 문제지의 통계 화면 예시와 같습니다. 즉 총운행거리는 행마다 (도착−출발)을 구한 뒤 부서별로 합한 값입니다. (이 계산은 이 자료에서 한 것이고, 원문에 풀이가 적혀 있는 것은 아닙니다.)

-- 부서별 합계 (총운행거리 = 도착km - 출발km 의 합)
select d.dept_code, d.dept_name,
       sum(v.drv_end - v.drv_start) as 총운행거리,
       sum(v.drv_money)             as 총주유금액
from tbl_drive v join tbl_dept d on v.dept_code = d.dept_code
group by d.dept_code, d.dept_name;

to_char(to_date(v.drv_date, 'yyyymmdd'), 'yyyy"년"mm"월"dd"일"')
